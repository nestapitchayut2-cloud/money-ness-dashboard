# ☀️ Weekend Lesson — วันอาทิตย์ที่ 9 สิงหาคม 2569

**🗓️ Phase 1 / Week 6: SQL Concept — จาก "ดูคำถาม" สู่ "แก้คำถามเอง"**

> สัปดาห์ที่แล้วรู้จัก query และหาส่วน SELECT/FROM/WHERE เจอแล้ว วันนี้ขยับอีกก้าว: ลองแก้เงื่อนไขในคำถามเอง + แอบดูว่า SQL "สรุปตัวเลข" ได้ยังไง (เหมือน Pivot Table ที่เคยทำ) สัปดาห์หน้าเริ่มเขียน SELECT/WHERE/GROUP BY เองเต็มตัว

---

## 📖 เรียนรู้อะไรวันนี้ (5 นาที)

ทบทวนไว: **query = คำถามที่พิมพ์เป็นภาษาที่ฐานข้อมูลเข้าใจ** และมี 3 ส่วนหลัก SELECT (เอาคอลัมน์ไหน) / FROM (ตารางไหน) / WHERE (กรองเงื่อนไขอะไร)

วันนี้เพิ่ม 2 concept ใหม่:

1. **แก้ WHERE = ถามคำถามใหม่** — ถ้าเปลี่ยนเงื่อนไขใน WHERE (เช่น เปลี่ยนชื่อประเทศ) ผลลัพธ์จะเปลี่ยนตามทันที นี่คือเหตุผลที่นักวิเคราะห์ใช้ SQL แทนการเปิดไฟล์ Excel คนละไฟล์สำหรับแต่ละเงื่อนไข — เขียน query เดียว แก้ตัวแปรเดียว ได้คำตอบใหม่ทันที

2. **Aggregate function = การ "สรุปตัวเลข" แบบเดียวกับ Pivot Table** — SQL มีคำสั่งอย่าง `SUM()`, `COUNT()`, `AVG()` ที่รวมข้อมูลหลายพันแถวให้เหลือเลขเดียว เช่น "ยอดขายรวมทั้งเดือน" หรือ "จำนวนลูกค้าทั้งหมด" — จำได้ไหมตอนทำ Pivot Table (สัปดาห์ 1-2) แล้วลาก field ไปใส่ช่อง "Values" มันรวมยอดให้อัตโนมัติ? นั่นแหละคือสิ่งเดียวกัน แค่ SQL ทำกับข้อมูลในฐานข้อมูลแทน

ทำไมต้องรู้: สองอันนี้คือหัวใจของงาน analyst จริง — กรองข้อมูล (WHERE) แล้วสรุปเป็นตัวเลข (SUM/COUNT/AVG) แทบทุก report การเงินสร้างจาก 2 ขั้นตอนนี้

## ⚡ ลองทำเลย (15 นาที)

ใช้เว็บเดิมที่เปิดไว้สัปดาห์ที่แล้ว ไม่ต้องติดตั้งอะไร:

1. เปิด https://sqlzoo.net/wiki/SELECT_basics
2. หา query ตัวอย่างแรกที่เคยดูสัปดาห์ก่อน (`SELECT population FROM world WHERE name = 'France'`)
3. **ลองแก้เอง** — เปลี่ยน `'France'` เป็นชื่อประเทศอื่น เช่น `'Thailand'` หรือ `'Japan'` แล้วกด **Submit** — สังเกตว่าผลลัพธ์เปลี่ยนตามทันที
4. แก้อีกครั้งเป็นประเทศที่สาม เพื่อยืนยันกับตัวเองว่าเข้าใจ pattern: **เปลี่ยนเงื่อนไข = เปลี่ยนคำตอบ**
5. เปิดแท็บใหม่ไปที่ https://sqlzoo.net/wiki/SUM_and_COUNT — อ่านคำอธิบายด้านบนสุด แล้วกด **Submit** ที่ query ตัวอย่างแรกที่เว็บเตรียมไว้ให้ (ยังไม่ต้องแก้อะไร)
6. เทียบผลลัพธ์ 2 แบบ: ข้อ 3-4 ได้ผลลัพธ์เป็น "รายการ" (หลายแถว) ส่วนข้อ 5 ได้ผลลัพธ์เป็น "เลขเดียว" ที่สรุปมาจากหลายแถว — นี่คือความต่างระหว่าง query แบบกรอง (WHERE) กับ query แบบสรุป (SUM/COUNT)

จบแค่นี้ — สัปดาห์หน้าเริ่มเขียน SELECT/WHERE/GROUP BY เองตั้งแต่บรรทัดแรก
