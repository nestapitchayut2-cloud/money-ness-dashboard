## 📖 เรียนรู้อะไรวันนี้ (5 นาที)

**Query คือ "คำถามที่พิมพ์เป็นภาษาที่ฐานข้อมูลเข้าใจ"** — แค่นั้นเอง ไม่มีอะไรลึกลับ

นึกภาพว่า Excel ที่ใช้มา 4 สัปดาห์ (Pivot Table, Power Query) เก่งกับข้อมูลระดับ "พัน-หมื่นแถว" แต่พอข้อมูลใหญ่ระดับ "ล้านแถว" (เช่น ธุรกรรมธนาคารทั้งประเทศ, ราคาหุ้นทุกตัวย้อนหลัง 10 ปี) Excel จะเริ่มอืดหรือเปิดไม่ไหว — ตรงนี้แหละที่ฐานข้อมูล (database) กับ SQL เข้ามาแทนที่

**SQL (Structured Query Language)** คือภาษามาตรฐานที่ใช้ "ถาม" ฐานข้อมูล เช่น:
- "ขอดูเฉพาะลูกค้าที่ซื้อทองคำเดือนนี้"
- "ขอยอดขายรวมแยกตามจังหวัด"

หน้าตาคล้ายประโยคภาษาอังกฤษง่ายๆ ไม่ใช่โค้ดโปรแกรมมิ่งซับซ้อน — 3 คำที่เจอบ่อยที่สุดคือ:
- **SELECT** = จะเอาคอลัมน์ไหน
- **FROM** = ข้อมูลมาจากตารางไหน
- **WHERE** = กรองด้วยเงื่อนไขอะไร

ทำไมต้องรู้:
- นักวิเคราะห์การเงินแทบทุกที่ใช้ SQL ดึงข้อมูลก่อนเอาไปทำ report — เป็น skill ที่ต่อยอดจาก Excel ได้ตรงๆ
- Power BI (Phase 2) ก็ต่อกับฐานข้อมูลด้วยหลักการเดียวกันนี้
- อ่าน data-related job post ภาษาอังกฤษแล้วจะเจอคำว่า "SQL" เกือบทุกใบ — รู้ concept ไว้ก่อนจะไม่งงตอนเจอจริง

## ⚡ ลองทำเลย (15 นาที)

ไม่ต้องติดตั้งอะไร ใช้เว็บ SQLZoo.net ได้เลย (สัปดาห์หน้าจะเขียน query เองในเว็บนี้ต่อ วันนี้แค่ "ดูของจริง" ให้คุ้นตา):

1. เปิด https://sqlzoo.net/wiki/SELECT_basics
2. เลื่อนดูตาราง **world** ตัวอย่าง — สังเกตว่ามันคือตารางแบบ Excel เป๊ะๆ (คอลัมน์ name, continent, population, gdp) แค่เก็บในฐานข้อมูลแทนไฟล์
3. เลื่อนลงไปหา **"1."** ตัวอย่าง query แรกที่เว็บเตรียมไว้ให้แล้ว (จะมีปุ่ม "Submit" ต่อท้าย) — ไม่ต้องแก้อะไรเลย
4. กด **Submit** ดูผลลัพธ์ที่เด้งกลับมา — สังเกตว่าผลลัพธ์คือ "คำตอบ" ของคำถามที่ query นั้นถาม
5. หาให้เจอในคำสั่งนั้นว่าส่วนไหนคือ **SELECT** (เอาคอลัมน์ไหน) ส่วนไหนคือ **FROM** (ตารางไหน) ส่วนไหนคือ **WHERE** (เงื่อนไขกรอง) — แค่ชี้ให้ถูก ยังไม่ต้องเขียนเอง

จบแค่นี้ — สัปดาห์หน้าเริ่มเขียน SELECT / WHERE เองบนเว็บเดียวกันนี้
